# 空检索回执修正与固定历史对照

日期：2026-09-06。**Akane 的空检索回执已改为先核对当前可见证据。真实 Engine 对照完成，新文案 5/5 直接完整回答，旧文案也有 5/5 答出两项事实，但其中 1 条表述有歧义、另 4 条额外读取了时间线。**这支持保留文案修正；本轮没有证明事实准确率提高，也没有稳定复现上一轮的完全漏答。

本轮新增 14 次真实模型 HTTP 请求，按实际时段费率估算 0.0296630 元；保守峰值记账增加 0.0593260 元。包含所有此前收费运行与失败，同一 50 元阶段预算累计记账 0.6018894 元，剩余 49.3981106 元，未决请求及预留均为零。供应商账单金额未知。

## 改动与问题来源

上一轮 `gallery_history__full__r1 / g_probe_memory` 中，“蓝色笔记本、周四晚上”仍在模型可见的用户原文和助手回复中，检索却返回了 `status=empty；returned=0`。原回执随后要求“请自然说明没有想起可靠线索”，模型最终要求用户重新提供物品与时间，见[前轮报告](../pilot_v2/actual_experiment_report.md)。

空检索只说明这次搜索没有返回匹配。特别是 live-turn 检索会排除已经可见的内容，它不能推出当前上下文也没有证据。

[宿主改动](../../../../AkaneCompanionLab/companion_v01/retrieval_engine.py)只调整有效空结果的后续指导：先核对当前可见对话和已有工具结果；证据足够时直接回答；证据不足且有明确日期/时段线索时，再读时间线；仍无证据时说明无法确认。查询参数、预过滤、检索返回状态和失败分支保持原有逻辑。

新文案已写入 Akane 源码。本次运行使用隔离的源码副本，没有重启用户正在运行的 Akane 进程；正常实例使用新源码启动后生效。完整的新旧文案保存在[结果数据](actual_results.json)中。

## 对照方法与控制

使用上一轮同一段五轮铺垫历史，每个分支重新经过真实 Akane Engine 恢复记录，并重放原始探针的第一次 `retrieve_memory` 工具选择。之后交由真实模型继续：允许正常补读、工具循环、输出验证和修复，最终由宿主接受并在当前轮保存回复。

这是**一个历史、一个已知空检索条件下的续答对照**。首个工具选择被固定，因此没有测试自主选择工具的能力；十个分支也不是十段独立历史。

另一个工作在准备期间新增了宿主文件，源码一致性门禁在付费前拦截了该次离线准备。最终运行使用已验证的原始 Akane 代码副本与 22 个公共内置角色资源，并核对了 384 个源码/模板/输入文件。原始清单的通用 `execution` 字段仍写作 `source_verified_original_packages_in_existing_akane_environment`；本轮准确含义是“在既有 Akane 环境中运行经过哈希验证的原始代码副本”。依赖二进制没有封存，不能视为全环境容器快照。
