# Akane + MemCore 多步长程实验

本轮检验真实 Akane 工具循环在多次 raw 压缩、任务版本更新和进程重启之后，能否继续完成任务、查清历史版本并承认资料缺失。场景完全虚构，工具只写入隔离研究资源。

**解释范围补充（2026-09-14）：**这是刻意安排历史恢复需求的合成压力检查，没有采样日常使用中完成任务后重读旧工具正文的频率。每条轨迹都包含旧版细节检查、长干扰输入和重启，其成本均值不能代表“任务完成后通常继续聊天或做其他事”的常规收益。后者需要独立比较无需旧原文、可见内容足够的追问、确需原文回读三类后续交互，见 [修订后的评估设计](../../akane_memcore_design_rationale_and_research_v1.md#5-研究问题与验证方式)。此补充不改变已执行协议、原始结果或评分。

**已结束并保留提前停止结果。**第三次付费尝试执行了计划 8 条轨迹中的 6 条完整轨迹，第 7 条中断，第 8 条未运行；共尝试 146/192 个用户轮次。6 条完整轨迹通过来源保留及重启检查，但存在错误方案写入、终答入库失败和证据描述错误。最后一条 HTTP 响应的 usage 超出请求输出上限，触发预先规定的停止规则；未决预留保持不动。结论、固定分母、全部失败和费用见 [实验结果](actual_results.md)，可复算数据见 [actual_results.json](actual_results.json)。

固定分母为 2 个场景族 × 2 种 operation projection 策略 × 2 次独立运行，共 8 条轨迹、192 个用户轮次、40 个记忆探针和 24 个方案修订。每条轨迹使用独立持久化目录和独立真实模型输出；不回放之前的选择或回答。相同轨迹内的探针有关联，不能作为 40 个独立样本计算普遍准确率。

## 流程与条件

| 轮次 | 内容 |
| --- | --- |
| 1 | 个人安排 |
| 2 | 阅读两份初版资料，选择满足约束的方案，保存并检查 draft_v1 |
| 3 | 阅读两份新版资料，更新数量、成本和负责人，保存并检查 draft_v2 |
| 4 | 明确修改个人安排 |
| 5–12 | 与任务无关的长输入，使历史经过真实 raw 压缩 |
| 13–14 | 当前负责人、未完成事项、最新个人安排探针 |
| 15–20 | 继续施加上下文压力 |
| 重启 | 关闭工作进程，在新进程中打开同一份隔离持久化数据 |
| 21 | 根据当前资料继续任务，保存并检查 final |
| 22 | 回查初版识别码和交接位置；此时资料工具不再提供初版 |
| 23 | 查询原始资料从未提供的费用字段 |
| 24 | 汇总当前交接要求，同时保留未完成事项和真实执行边界 |

`full` 使用 `full_until_raw_compaction`，`card` 使用 `compact_after_terminal`。两者共享 raw token trigger 4000、batch ratio 0.67 和真实宿主的其余记忆配置。脚本保留真实时间戳，因此这是加速上下文压力实验，并非实际跨天等待实验。

首次付费尝试在重启索引预热阶段中断，20 个用户轮次和 45 次已结算调用全部保留，详见 `interrupted_attempt_01.json`。后续付费尝试统一把宿主已有配置 `EMBEDDING_REINDEX_BATCH_SIZE` 设为 1，并把脚本的启动等待上限设为 600 秒。生产 embedding 独立预检用合成历史副本，在约 10.4 秒内恢复全部 80 条索引记录，保存上下文及方案精确一致，且没有调用模型；证据见 `production_restart_preflight.json`。该调整不截断 embedding 文本、不改变模型，也不把预检当作记忆回答成绩。

真实宿主使用 DeepSeek V4 Flash、关闭 thinking、关闭养成、非流式响应以及原有分角色 temperature。聊天保持原生 `max_tokens=2048`；摘要等基础调用保留宿主原本未传输出上限的请求。账本对后者按已核验的模型最大输出 393216 tokens 预留，而不改写请求。长程实验将单次输入准入上限显式设为 65536 estimated tokens，usage 返回后再检查真实输入量；早期短实验的默认上限仍为 30720。

聊天和后台摘要的物理请求串行完成预算预留及 usage 结算。所有付费调用复用原阶段 50 元账本，累计包含之前的实验和失败；不另起预算，不自动重试不明费用。上下文、传输、费用、来源变化或隔离错误会中断后续调用并保留固定分母。语义答错照常计分，不触发重采样。

第二次付费尝试在第 7 条轨迹中遇到实验脚本误判：路径正则把嵌套 JSON 中 `content:\n` 等结构标题的末尾误当作盘符路径，阻止了下一次 HTTP 请求。该次实际执行的 166 轮、405 次付费调用、语义与最终格式失败都保留在 `interrupted_attempt_02.json`；其中 32 个探针有回答，另 8 个被中断或未执行。修正只涉及实验脚本的检查逻辑：先解码结构化字符串，再判断路径语法；真实路径、UNC 路径和凭据控制仍须被拦截。相同原始工具结果已通过公开 API 读回验证，修正后不再误报。第 11 次离线验收及完整回归通过后，第三次付费尝试按全部 8 条轨迹的原计划从头开始，没有挑选重跑某个错误答案；实际在第 7 条停止。

## 真实性与验收

执行对象是经过来源哈希校验的真实 Akane Python 源码、既有依赖环境和生产 embedding。宿主仅通过依赖工厂接入实验 transport、embedding 和允许的工具；原有 prompt 构造、原生工具调度、输出修复、落库及后台维护流程保持执行。源码证据覆盖公开代码、协议和人设资源，二进制依赖没有另行封装，因此不声称环境可逐字节复现。

公共 API 观察器保留原方法的返回值与 Future，记录实际完成、压缩 generation 和索引预热结果。脚本在用户可见回复返回以后等待后台安静，再提交下一条合成消息；它不强制调用压缩、不代写摘要、不向模型注入诊断读回结果。

付费前必须通过真实 Engine + Mock HTTP 的离线验收。离线脚本包括一次无效最终格式、一次错误方案及其修正；这些脚本只验证宿主机制，不计算模型能力成绩。离线使用单独且明确标记的测试账本与 hashed embedding，不能进入付费路径。验收检查：

- 两种策略都经历至少两次实际 raw 压缩，早期 assistant/tool 记录已退出 raw 可见上下文。
- 所有最终回复非空，并与唯一的公开 `complete_turn` 结果绑定。
- 三个方案修订均检查通过；错误算术先被拒绝再修正；初版未被覆盖。
- 旧工具正文的完整公开渲染内容在初次保存、压缩后及重启后保持相同哈希；模型原生回读也实际收到旧正文。
- 新旧进程不同，重启后的 provider projection、元数据、状态和方案文件精确一致，正常执行索引预热。
- 网络审计无真实连接或尝试，所有 HTTP 响应均来自明确的 mock transport。

## 评估与复查

`scenarios.json` 和 `run_manifest.json` 是执行输入；`answer_key.json` 只供实验完成后的评估读取。模型只获得当轮用户输入、正常可见记忆、实际工具描述与实际工具结果。方案检查器的结构化约束与用户提供的合成资料一致，检查结果不返回期望答案或旧资料全文。

新版资料在服务端仍可重新查询，因此当前状态探针和任务续作可以通过当前资料完成；这类成功只说明任务连续性，不能单独证明历史召回。初版资料在新版发布后不可再从资料服务取得，旧版探针必须依赖保存的历史。个人安排只来自对话记忆。评估会分别记录答案是来自可见记忆、记忆工具还是当前资料工具。

评估同时检查真实保存的方案内容、检查回执、40 个探针的语义答案、来源是否支持答案，以及全部回复是否误称已执行真实业务。报告分别给出完成率、任务质量、当前/旧版混淆、缺失证据处理、调用与费用、上下文体积、实际压缩及恢复证据；不把 mock 输出或诊断回读当成模型成绩。

本轮仍然是小规模、单模型、两个合成任务族的机制验证。它可以暴露可复查的失败，不能证明任意真实任务的长期可靠性。
