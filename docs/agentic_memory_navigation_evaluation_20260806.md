# Agentic Memory Navigation：真实会话基线评测（2026-08-06）

> 在这次真实样本中，语义检索 20 次调用没有产生一条可直接支持答案的结果，
> 但聊天模型仍能通过记忆目录、摘要节点、局部展开和原始时间线解决大部分问题。
> 这说明语义检索可以是加速器，但不必成为记忆可达性的唯一入口。

本文记录一次匿名、只读的线上会话审计。它不是排行榜，也不证明所有模型、提示词和
数据集都会得到同样结果；它用于回答一个更基础的问题：当向量/关键词入口失灵时，
MemCore 提供的其它路径能否让模型继续查找、核对并形成有证据的回答？

## 评测范围

- 时间：2026-08-06 17:00–19:00（UTC+8）。
- 场景：一个真实的私聊会话，两个彼此隔离的角色记忆域。
- 样本：15 个触发记忆工具的用户问题。
- 数据：已保存的用户问题、tool action/observation 轨迹和最终回复。
- 审计方式：只读检查；没有修改记录、重放模型、补写工具结果或重建索引。
- 提示词状态：取自后续记忆工具提示词优化之前的线上表现。

为保护真实会话隐私，本文泛化了问题内容，不公开用户标识、会话标识、数据库路径、
source ID、人物私密信息和基础设施细节。数量、调用顺序、耗时与结果状态保持原样。

| `retrieve_for_turn` 返回 `found` | 2 |

| `open_memory` 调用 | 7 |

两次 `found` 的 Top-6 都是与问题无关的记录，因此不能把它们算作有效命中。尽管如此，
大部分最终回答仍与可见记忆或只读真相源一致。本文不发布一个人为的“总准确率”：
样本里既有可逐字核对的事实，也有关系和经历的概括，并非每个回答都有独立金标准。

这个基线最重要的结果不是“语义检索也能用”，恰恰相反：在该样本里它基本不可用；
真正承受住失败的是多路径导航能力。

## 模型实际使用的闭环

典型路径不是反复改写同一个向量查询，而是逐步缩小证据范围：

```text
时间未知或第一次尝试
  -> retrieve_for_turn
  -> 命中不足时 browse_memory 浏览时间范围内的紧凑卡片
  -> open_memory(content) 阅读候选摘要
  -> 必要时在选中节点内继续检索
  -> 需要精确时间、原话或上下文时 read_timeline / open_memory(sources)
  -> 证据足够则回答；仍无证据则明确说没有找到
```

这里的关键不是强制模型执行固定工作流，而是给它一组可以互相接力、每一步都能缩小
范围的工具。聊天模型保留选择自由；提示词只需说明一条高成功率的推荐路线。

## 代表案例

### 1. 从宽目录恢复精确分钟与上下文

用户要求回忆某首歌曲第一次被提到的精确过程。第一次语义检索为空，模型随后浏览月初
记忆目录、打开候选摘要并读取某一天的时间线，先排除了另一首容易混淆的歌曲；在连续
追问中，它又定位到月底约四十分钟的局部时间线，恢复了四个相邻时间点、两次出现顺序
及其前置活动。

```text
retrieve: empty
  -> browse: 月初目录
  -> open: 候选摘要
  -> retrieve: empty
  -> timeline: 排除相似事件
  -> timeline: 缩小到约四十分钟
  -> 恢复精确分钟、顺序和上下文
```

后续 cursor 续页又返回 24 个完整逻辑单元，支持模型继续回答与童年经历、怀旧情绪和
陪伴关系有关的问题。这个案例体现的是：目录负责定位，摘要负责判断相关性，原始时间线
负责精确核验；任何一层都不必独自承担全部任务。

### 2. 卡片与摘要直接解决外观变化问题

用户询问几天内角色外观如何变化。语义检索为空后，模型浏览对应日期范围，选择相关
长期记忆节点并打开摘要正文，直接从摘要完成回答，没有无必要地展开整棵 raw 来源。

```text
retrieve: empty
  -> browse: 目标日期范围
  -> open(content): 相关节点
  -> 从摘要回答
```

该路径耗时约 19 秒，工具结果约 12,420 字符。它说明摘要卡片不是“次等搜索结果”，
而是低上下文负担的导航索引：模型先判断“答案大概率在哪一段”，再决定是否深入。

### 3. 在错误 Top-6 之后完成否定性检查

用户询问是否曾提到一种身体症状。语义检索返回了六条无关日常对话；模型没有拿高分
候选硬答，而是拒绝这些结果，浏览 53 张卡片、打开一条摘要，并沿四页时间线继续检查，
最后说明没有找到记录。只读 SQLite 真相源检查也没有发现该症状的历史原话。

这说明确定性目录与时间线不仅能找“存在的事实”，也能帮助模型在错误候选之后继续做
否定性查找。不过，否定结论的强度必须和实际覆盖范围一致：本次 trace 能证明模型持续
检查了多个范围，不能仅凭一句模型自述证明它形式化遍历了全部历史。

### 4. 正确答案不等于正确的证据路径

另一个精确时间问题中，模型给出的分钟与数据库真相一致，但当前轮只读取了错误日期
范围；答案更可能来自已经可见的摘要或上下文，而不是本轮工具结果。被追问后，模型一度
错误声称“刚刚重新读取了原始时间线”，随后才承认没有执行新的工具调用。

这个反例很重要：MemCore 能保存并暴露真实工具轨迹，但模型仍可能把“我记得答案”
描述成“我刚核对了原文”。因此评测必须区分：

- `context_recalled`：答案来自当前上下文，当前轮没有新增证据。
- `summary_supported`：可见摘要支持答案，但没有核对原始记录。
- `raw_verified`：当前可见 raw 或本轮工具结果直接支持答案。

事实正确性和证据来源真实性是两个验收项，不能互相替代。

## 观察到的成本

多路径恢复提高了失败时的可达性，但不是零成本：

下表按单个用户问题统计；上面的精确分钟案例跨越了连续追问，因此整条案例链的调用数
不能用其中任意一行代替。

| 匿名问题类型 | 调用数 | 工具输出字符 | 观察耗时 |
| --- | ---: | ---: | ---: |
| 精确事件复原 | 1 | 11,080 | 13 秒 |
| 人生阶段判断 | 7 | 53,570 | 90 秒 |
| 歌词/歌曲细节 | 5 | 38,324 | 46 秒 |
| 否定性症状检查 | 7 | 131,868 | 125 秒 |

因此“最终大概率能翻到”不等于“第一轮就便宜”。更好的语义排序、卡片标题与关键词、
更准确的时间提示仍然有价值；它们应该缩短路径，而不是取代目录、摘要和原始证据这些
可靠退路。

## 这次评测支持什么结论

1. **记忆可达性不必绑定单次向量召回。** 语义入口没有有效命中时，模型仍能换用
   目录、节点正文、局部时间线和来源证据。
2. **摘要是导航层，也是可直接回答的证据层。** 摘要足够时停止下钻，可以保留体验并
   降低上下文负担；细节不足时仍有稳定 ID 继续打开来源。
3. **模型主动性是系统能力的一部分。** MemCore 不额外内置 router；当工具契约清楚、
   结果可继续导航时，负责最终回答的模型可以自行决定是否继续、换路或停止。
4. **原始时间线提供可核验退路。** 精确时刻、原话和相邻上下文不需要依赖摘要猜测。
5. **失败应保持诚实。** 空结果、无关候选、分页和证据不足都必须可见，不能伪装成
   “没有发生过”或“已经核验”。

可以把这组能力概括为 **Agentic Memory Navigation（主动式记忆导航）**：语义检索是
快速入口，目录和摘要是地图，原始时间线是证据底座；模型可以在这些层之间主动移动，
直到找到足够证据，或诚实地说明当前没有找到。

## 这次评测不支持什么结论

- 不证明当时的语义检索质量良好；样本反而暴露了明显的召回/排序问题。
- 不证明 MemCore 达到 SOTA，也不是与其它记忆框架的受控对比。
- 不证明 15 个问题全部经过 raw 核验，或每个最终回答都完全正确。
- 不证明任意聊天模型都会持续使用工具；模型能力和宿主提示词仍会影响行为。
- 不证明一次否定性查找已经覆盖全部历史，除非工具返回可验证的覆盖元数据。
- 不代表当前 HEAD 的回归结果；它是指定时间、指定部署与指定提示词状态的观察基线。

## 后续回归建议

以后可用同一问题集重复评测，并至少记录：

| 维度 | 建议定义 |
| --- | --- |
| direct semantic utility | `retrieve_for_turn` 的结果是否直接包含回答所需证据，而不只看 `found` |
| end-to-end resolution | 最终是否找到答案、正确拒答，或仍未解决 |
| evidence grade | `context_recalled` / `summary_supported` / `raw_verified` |
| navigation cost | 工具调用数、返回字符/token、总耗时、cursor 页数 |
| persistence | 首次失败后是否继续换路径，以及在哪一步停止 |
| negative coverage | 否定结论实际覆盖的日期、节点、页数和未覆盖区间 |
| provenance fidelity | 模型对“答案从哪里来”的叙述是否与 action/observation trace 一致 |

这组指标能同时衡量“快不快”“找不找得到”和“有没有说清证据”，避免只用 Top-k 命中率
评价一个本质上支持多步导航的记忆系统。
