# 语义检索与关键词目录升级讨论稿

日期：2026-09-22，更新：2026-09-30。状态：关键词目录、参与者目录、批量原文回溯与发言者筛选均已实施并接入 Akane。下文的当前代码核对是实施前基线，语义检索调整与原文命中归组仍为讨论方案。现行读取契约见 [读取 API](memory_read_api_v1.md)。

本次实施：`browse_memory(keywords, keyword_match)`；词池合并并去重原始来源、阶段摘要和长期摘要自身的实体/主题标签；卡片分别展示摘要标签和命中词；同步微调统一标注与摘要提示词。词池按当前 SQLite 来源关系读取，不新增持久化词表。关键词结果变化时，旧游标明确要求重新查询；不保存历史快照。

## 目标

在当前完整工具轮与终局回执机制下，让模型一次看到足够的有效证据；同时为“不记得日期、但知道主题或名称”的查询增加可预测的目录入口。保留时间范围、原始来源和按需展开能力，不把每次查询都变成固定的多工具流水线。

## A. 放宽一次有效召回

建议将默认条数、宿主允许上限、内部候选数量分开。初始讨论值为默认 16、请求上限 48，可配置；这只是试验起点，不是已测出的最优值。native tool 暴露有界 `max_matches`，结果反馈实际采用的上限。

候选池不能简单无限按结果数乘十扩大，需单独界定与测量。先补齐逻辑轮次、去除同轮和多层重复，再计算最终结果位，必要时从已召回候选中补足；没有足够相关证据时不为了凑数加入噪声。

保留 raw 优先、来源验证、命名空间、工具轨迹授权和当前可见记忆排除。目录查询则应维持其浏览语义，不能为了去重静默删掉时间目录已有的覆盖信息。

先让 native retrieve 只发送一份证据正文，另保留 ID、时间、分数与导航元数据。Python 诊断对象可以继续保留不同视图，不能直接将全部视图重复装进 provider 结果。这项可减少提高条数时的不必要放大。

启用 `compact_after_terminal` 并成功完成当前轮后，符合条件的长观察会退为可回读回执。这使一次多看一些证据具有合理性；本轮仍需真实读入这些内容，宿主的即时上下文预算继续有效。默认的 `full_until_raw_compaction` 不会自动获得相同的终局压缩行为。两种策略均不应被偷偷改动。

## B. 给现有目录增加关键词入口

建议扩展 `browse_memory`，保留四工具结构。拟议调用，仅作接口讨论：

```python
browse_memory(
    keywords=["GPT-SoVITS", "字幕"],
    keyword_match="any",  # any 或 all，必须有明确定义
    node_types=["episodic"],
    page_size=50,
)
```

`keywords` 是查询参数，不再建立一套与 `entity_anchors/topic_terms` 竞争的写入字段。此通道匹配已有实体/主题标签；无需调用 embedding。无日期时允许在授权范围内查目录，有明确日期时再叠加时间硬范围。既有无关键词时间浏览保持行为。

已实施版本在统一归一化后按“已存标签包含查询词”单向匹配，保留专名符号，不自动猜同义词或未知实体。精确与包含命中同时参加查询，`any` 为至少一项，`all` 为每项均有标签依据；同一标签可满足多个查询词。`keyword_hits` 每个查询返回一个已存词条作为依据。未命中返回明确空结果，不自动把关键词查询变成语义结果。近义表达继续交给现有混合检索。

初版继续按确定性时间键排序、游标分页。游标冻结关键词、匹配方式、节点类型、命名空间与时间范围；新增/强化摘要时使用一致的查询版本或快照策略，避免跨页重复、遗漏或范围漂移。相关性排名不是此次时间目录的隐式副作用。

可以后续评估“标题/正文的词面查询”，但它和严格标签查询需要分别说明命中来源，不能混为同一种保证。

## C. 目录卡片同时返回关键词

为目录卡片增加 `entity_anchors`、`topic_terms`；关键词查询再增加 `matched_terms` 与命中字段/来源类型。继续返回现有 memory_id、标题、catalog_hint、绝对时间范围、来源数量、是否可展开。

以下是虚构的结构示例，不代表数据库中已有此记录：

```json
{
  "memory_id": "episode_example",
  "memory_title": "讨论配音与字幕制作",
  "period_start_at": "2026-09-15T14:00:00+08:00",
  "period_end_at": "2026-09-15T14:30:00+08:00",
  "entity_anchors": ["GPT-SoVITS", "达尼娅"],
  "topic_terms": ["配音", "字幕", "音画同步"],
  "matched_terms": ["字幕"],
  "has_content": true,
  "has_sources": true
}
```

展示标签应去重、优先突出本次命中词并控制单卡体积；底层检索范围不能因为展示只取前几项而同步缩水。若显示的是来源标签而非摘要正文中的概括，要明确其身份：它说明原文包含此线索，不保证摘要正文已保留答案。

标题卡片仍是线索。足够时直接回答，需要正文时 `open_memory(content)`，需要原始依据时展开 sources 或精确时间线。不要把标签列表当成事实句子。

## D. 完善标签生成与继承

继续使用已有字段分工：`entity_anchors` 放准确已知名称/别名；`topic_terms` 放具体对象、议题、动作和关系短词。鼓励保留有辨识度的名词，但“取消、替换、退款、报错”等动作可能决定查询，不能规定只许名词。

改进摘要提示词：覆盖来源中不同的实际话题，尤其保留容易被总标题省略的次要对象；使用来源支持的短语，不堆泛词、猜答案或编造别名。不要求每条固定填满一个数量。

标签应在读完整来源时生成，而不是只从已经压缩过的摘要正文二次猜测。摘要模型已有这次读取，不增加每轮在线检索的 LLM verifier/router。

在索引侧补来源标签的可检索投影，弥补“模型非空字段覆盖来源标签”的遗漏。不要直接把所有后代标签无限并入长期记忆的语义描述；要区分“当前摘要概括的主题”与“来源包含的线索”，后者记录确切 lineage。派生投影可以由已有元数据重建，不改写原文。

父摘要来源线索命中后，要能沿 memory_id 限定来源范围继续读取。重摘要、强化合并、定向遗忘、删除和 reindex 必须同步更新派生标签；删掉的来源不能留下可命中的旧标签。

关于“一来一回”：简单聊天可看作一轮，但当前 raw 标注不等于一对消息的联合标注。完整 turn 也可能含多输入、工具和外部事件。若以后增加整轮标签，应由完整 turn 派生索引并保留说话者与源 ID，不能把助手补充的观点倒写成用户事实。本次先改善摘要范围内的标签覆盖，raw 标注归属维持当前契约。

## E. 验证方式与建议实施次序

依次做：模型结果正文去重与限额拆分；目录标签输出；标签关键词选择器与分页；摘要提示及来源标签继承投影。

功能验证覆盖：无日期关键词查询、any/all、大小写/全半角/明确别名、完整中文短语、空结果、游标稳定性、跨命名空间隔离、旧数据库无标签、来源删除、同轮重复命中与补足、当前可见排除、operation/material 显式读取边界。

效果验证用真实 embedding 和有证据标注的查询，对比原 6 条与更大返回数、混合检索与目录关键词入口。检查首次结果是否包含答案证据、调用轮数、无关内容、当轮输入量以及后续请求的累计输入量；不把相似度高或“返回更多”直接当成功。

工作负载应包括大量查完即继续其他聊天/任务的情况，再加入适量追问与原文核对。不要让所有案例都强制回读，避免把实际常用路径测成另一种工作流。

## F. 原文命中映射到目录：可选的第二阶段

后续讨论提出：在后台召回更多原始对话，再依据强来源关系汇总为少量摘要目录卡片。这个方向与关键词池共用目录输出，不需要复制一套记忆真相。

现有基础已经具备：messages 保存 summary_id，摘要保存 source_ids，存储层支持 `resolve_lineage_source_ids(include_ancestors=True)`。不过当前通用祖先解析会扫描作用域内的摘要来源建立反向关系；高候选量路径应批量解析或增加受约束的反向索引，不能逐命中重复扫描整套历史。

拟议数据流：

```text
原始标签池的关键词匹配 ───────────┐
                               ├→ 摘要目录 ID → 同一套卡片 → 正文/原文
原文的语义或混合候选 → 来源归组 ─┘
```

“标题”是展示字段，稳定的 summary_id 才是归组键；相同标题不能导致不同历史被合并。

目录卡片使用统一的标题、时间、展示关键词与展开入口。不同检索路径只附各自的匹配依据：关键词路径显示命中词；语义路径可显示少量命中原文短句与源 ID。原文含次要话题但摘要标题没有提到时，匹配依据可以帮助模型正确判断这张卡片。

候选原文数量与最终返回目录数量分开。后台如命中很多原始条目，按摘要 ID 归组后可能只剩少量目录；不要先按现有 6 条最终正文结果截断，再企图得到覆盖更广的目录。

初版目录以直接的阶段摘要为归组目标，不将一个命中同时展开为所有层级祖先。尚未进入摘要的记录保留原始入口，失效/缺失来源明确报告。已可见摘要下的原文细节仍可检索；归组不能把这类有用的细节再次永久排除。

组内相关性先以最强命中为主，多个独立轮次的支持可作有限加分。不能简单按命中条数求和，防止长段聊天或重复表述长期占据前排。限制重复组占用候选；不足时再取后续候选，不为凑满目录引入没有相关依据的组。

建议优先级：

1. **本轮正式建设**：同一套目录卡片、展示关键词、完整来源标签池、确定性关键词目录查询；并完成之前讨论的正文去重与限额拆分。
2. **小范围对照试验**：复用现有向量索引，比较“直接搜摘要”与“搜原文再归组”，两者采用相同目录输出规模。暂不改变默认检索行为。
3. **证据支持后再决定融合**：只有新路径稳定补到旧路径找不到的相关目录，并且增加的查询成本可接受，才决定默认启用或目录级融合。不增加一轮 LLM 路由或在线验证。

词池查询本身不调用 embedding，不代表当前整个 MemorySystem 的构造与写入可以省略 embedding 配置。语义试验复用已接的模型与已建立的索引，不要求为了它再接第二个向量模型。

对照查询应包括准确名称、近义描述、摘要遗漏的小话题、一个摘要内大量重复命中、跨多段历史的主题、无关查询以及不存在摘要的原文。检查正确目录是否出现、匹配依据是否足以选择、最终证据能否打开、实际工具次数和输入量，而不是只统计后台搜到多少条。

## G 群聊参与者执行单

确认日期：2026-09-30。状态：已实施并接入 Akane；参与者展示、精确筛选与后端重启均已验收。

为每批压缩的原始对话保留一份简单、去重的参与者名单，与记忆标题、关键词一同提供给聊天模型，帮助它判断哪段历史涉及目标人物。名单不区分发言者、说话对象，也不建立人物关系。

### 已确认规则

- **系统提取身份**：参与者来自原始消息已有的结构化身份信息，复用现有 Actor 和参与者收集能力。昵称由平台提供；Akane QQ 入口优先取群名片，其次取 QQ 昵称，缺失时使用已有缓存或群成员信息查询。总结模型负责标题、话题和摘要，不猜测昵称或 QQ 号。
- **按稳定 ID 去重**：同一个人即使改过昵称也只列一次；使用本批原始记录中最后一个非空昵称。重名但 QQ 号不同的人分别保留。
- **昵称加 QQ 号**：QQ 参与者展示为 `小林（QQ 123456）`，昵称和 QQ 号各出现一次；没有昵称时只显示 `QQ 123456`。平台未提供 QQ 身份时使用实际已有的名称或平台 ID，不编造号码。MemCore 内部继续使用通用 Actor ID，QQ 展示规则放在适当的宿主渲染边界。
- **一份扁平名单**：标题卡片用清楚的“参与者”字段展示名单，不附角色分类、关系标签、发言次数或多套别名字段。
- **只呈现一次**：模型结果使用结构化名单或清楚的文本名单择一呈现，不再附另一套重复名单；参与者字段内每人的昵称和 QQ 号各显示一次。不要为展示名单而额外把所有参与者塞入关键词，原有来源支持的检索标签照常保留。存储与可信 Python API 可继续保留结构化 `participant_refs`。
- **缺失如实表示**：没有可用参与者信息时返回空名单或“参与者未记录”；不让模型从正文中被提到的名字猜出参与者。名单帮助选择记忆，具体是谁说了哪句话仍依据打开后的原始记录。
- **精确筛选参与者**：扩展现有 `browse_memory(participants=[...], participant_match="any"|"all")`，不新增工具。可传一个或多个已知昵称或稳定 Actor ID；Akane 接受 QQ 号并规范为 `qq:<号码>`。ID 精确匹配，昵称在宽度、大小写与空白归一化后全等匹配，不做子串或语义猜测。只匹配已记录的昵称，改名后优先使用 QQ 号；重名返回所有匹配卡片并保留号码辨认。
- **组合条件**：`any` 表示名单含任意一个查询人物，`all` 表示每个人物条件均有匹配。可单独按人物查询，也可与关键词、日期、节点类型组合；不同维度之间取交集。多人在同一卡片只表示这批原始记录涉及这些人，不建立关系或同话题判断。
- **旧数据与分页**：缺失名单可沿授权范围内的精确来源读取已有 Actor 字段补齐，不调用总结模型、不读取正文猜身份。参与者筛选条件与结果指纹冻结进 cursor，结果变化要求按原条件重查；覆盖统计仍描述筛选前的历史。

以下为虚构的模型可见示例，实际结果仍保留必要的 memory_id、时间和展开入口；参与者只展示一次：

```text
标题：文旅答辩方案讨论
关键词：文旅、答辩、方案
参与者：小林（QQ 123456）、小周（QQ 654321）
```

## H 批量原文回溯与发言者筛选执行单

确认日期：2026-09-30。状态：已实施并接入 Akane，回归、安装后适配链、后端重启和在线工具契约均已验收。模型可一次回溯多张相关卡片，也能只读其中指定人的原始发言；返回内容足以判断归属、范围和下一步，正文只呈现一次。读取速度与有限输入量均作为验收条件。

### 入口与读取范围

复用 `open_memory`，为 `view="sources"` 增加 `memory_ids` 批量入口，以及可选的 `speaker_ids`。两项沿同一条精确来源链读取，不新增独立工具、总结模型调用或检索索引。现有单卡片完整展开及批量 `card/content` 保持原有含义。

调用示例：

```python
# 批量查看所选阶段摘要卡片的完整来源对话。
open_memory(memory_ids=["episode-a", "episode-b"], view="sources")

# 只看同一批卡片内指定人的原始发言。
open_memory(
    memory_ids=["episode-a", "episode-b"],
    view="sources",
    speaker_ids=["qq:123456", "qq:654321"],
)
```

`memory_id` 与 `memory_ids` 互斥。批量结果按请求顺序分组，重复请求 ID 只展开一次；每个节点独立报告成功、空结果或失败。一张卡片缺失不丢弃其他成功结果。

每个节点只沿自身已存来源读取。阶段摘要返回原始来源；长期摘要的普通 `sources` 仍返回子阶段卡片，不自动递归铺开整棵历史。首版发言者筛选只用于阶段摘要的原始来源，其他节点明确报告不支持该筛选，不能自动改读更大的范围。Akane 每次仍指定一个目标 `conversation`，后续打开、分页和扩窗继续受同一会话权限约束。

### 发言者筛选

目录的 `participants` 表示这段记录涉及谁，用于找候选卡片；回溯的 `speaker_ids` 匹配实际用户消息（普通、被动群聊及语音）的 Actor ID。助手回复、接收对象、被 @ 的人和事件参与者不能因此被当作该人的发言。无需给目录增设人物角色或关系字段。

模型优先使用已返回的稳定 ID。Akane 可将字符串 QQ 号规范为 `qq:<号码>`；MemCore 只做稳定 ID 全等匹配，不用昵称、正文名字或模型推断补身份。多人选择表示返回任意被选中的人的发言，不增加 `any/all` 参数。改名不影响 ID 匹配，原话仍展示当时记录的昵称。

未提供或为 `null` 时不筛选；显式空列表、非字符串、空白 ID、控制字符及错误参数组合返回结构化错误，不退回完整展开。首版 `speaker_ids` 仅适用于 `view="sources"`、`projection="conversation"`；与 `card/content` 或 `full/tools` 组合时拒绝调用。只有发言者筛选时，结果明确标为 `speaker_filtered`，仅返回匹配的完整原始消息，不冒充完整对话单元。默认完整展开继续保持完整逻辑单元。两种读取都不截断句子，不从摘要生成缺失原话。

所有保留来源均可检查且身份已知时，空结果表示这批来源内没有匹配发言。身份未记录、来源缺失或尚有下一页时分别说明，不能据此断言该人没有说过。每条返回原话保留 `source_id`，上下文不足时用现有 `read_timeline(anchor_source_id=..., before_turns=..., after_turns=...)` 查看附近完整对话；不默认附带其他人的整段发言。

### 批量分页与返回预算

每张卡片保持自己的来源分页，cursor 冻结卡片、投影、发言者条件、会话范围及来源指纹。续读只传对应卡片的 cursor；不能在续页时换人、换卡片或扩大会话。在现有来源完整性检查之外增加来源指纹校验，来源关系或匹配身份变化时明确要求重新展开，不能继续使用过期位置。Akane 必须包装并检查嵌套的每个 cursor，逐页重新检查权限和开关；未展开节点的最小下一步调用也必须携带同一目标会话。

首版 native 批量 `sources` 初始最多 8 张，`native_sources_max_cards` 可配置为 1–32；这是工程值，不声明最优。多张卡片共用 `native_timeline_page_token_budget`（默认 12000），不按卡片数倍增；另有 `native_sources_page_utf8_budget`（默认 48000 字节）为宿主 cursor 签名和最终包装留余量。模型不能改变这两个预算；`page_size` 只限制各卡片的逻辑组数量。可信 Python 的零预算诊断调用保持独立。发言者选择在 native 侧最多 16 项。

分配预算时先按请求顺序尽量覆盖各卡片首个完整组，再在预算内继续读。默认完整组为完整对话单元，筛选组为该单元内所有匹配原话。预算不足的卡片标为未展开并提供最小下一步调用；已读一部分的卡片返回自己的 cursor。一个组超过预算时允许完整返回一次并标明超量，停止追加其他正文。遇到实际传输上限则返回明确过大状态与可重新读取的入口，不能静默切正文或声称读取完毕。

同一响应页内，按 `source_id` 去重正文，并保留它属于哪些所选卡片。后续组引用本页已呈现的原文，不把重复来源算作不同发言；每次续读页保持可独立理解，不依赖上一轮仍保留整段正文。

### 模型看到的必要信息

会话范围、完整或筛选模式、实际发言者条件在页头只出现一次。每张卡片只保留 ID、简短标题、来源时间范围、该卡片状态、已返和待返数量、必要的下一步。原话只包含当时的发言者昵称及 ID、时间、`source_id` 和一份正文；各卡片内按原始时间及稳定顺序排列。不存在异常时省略空错误、空缺失清单和空下一步。

不重复发送卡片摘要、关键词、全部参与者、完整来源 ID 清单、SQL 统计或哈希。缺失及未知身份只给有助于判断证据范围的数量与说明。可信 Python 可保留诊断结构；native 只输出一份原文表示，不能同时把正文放进结构化消息、渲染文本及另一套 snippets。

回执保留有界的节点状态、范围、筛选、分页与必要读取锚点，不复制正文或整棵来源树；回执仍不能替代模型实际收到并在本轮存储的 observation。终局压缩与固定工具快照沿既有生命周期更新，不额外修改历史消息或制造第二套身份真相。

### 读取速度约束

模糊检索、dense/BM25 排名及其预过滤路径保持不变，不增加 LLM 判定、人物推断或第二次 embedding。来源在 SQL 中按 400 个 ID 分批读取，批量卡片先合并并去重来源 ID；发言者筛选先读轻量身份列，仅加载实际命中的用户正文。先划分完整逻辑组，再按本页选择延迟投影和渲染；共享组复用同一投影，页面预算探测复用已渲染消息，未返回的组不提前渲染。

测试同时约束读取次数和实际工作量，避免逐卡片查询或重做整棵树的正文投影。性能记录采用隔离数据库与同机旧版对照，注明来源数量、返回量、输入字节和 SQL 次数；它只说明该测试场景，不能代替真实模型与数据库规模的延迟测量。

工具描述已按下面一段所述逻辑精简，替换原有相应说明，不在 persona、schema、playbook 再各叠一份同义长规则：

> 摘要不足或需核对原话时，用 open_memory 的 sources 展开所选卡片，可批量传 memory_ids。speaker_ids 只筛实际发言者；片段缺上下文时，用 source_id 调 read_timeline 扩窗。每张卡片独立分页，续读只传对应 cursor；空结果只说明此次范围未命中。

参数 schema 负责类型、精确 ID 和不合法组合；动态结果负责具体状态、筛选范围与下一步。投影、显式工具轨迹与材料授权等现有必要规则继续保留，但不借此把整篇执行单写进模型提示词。
