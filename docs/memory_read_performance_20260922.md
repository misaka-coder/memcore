# 记忆读取性能检查（2026-09-22）

本次同时将目录关键词改为“已存词条包含查询词”的单向匹配；具体契约见
[读取 API](memory_read_api_v1.md#browse_memory)。`keyword_hits` 返回每个查询词对应的
一个已存原词条，精确和包含命中共同参加查询。

## 测量方法

使用 [隔离基准脚本](../examples/benchmark_memory_reads.py)：内存 SQLite、2,000 条合成
原文（每条约 1,300 中文字符）、100 条阶段摘要、5 条长期摘要。使用本地
`HashedEmbeddingProvider`，仅供可重复性能检查。先暖机，再记录 5 次读取的中位耗时；
SQL 数量在独立一次调用中记录。数据创建和索引加载不计入读取耗时。没有读取生产对话、
调用网络 embedding 或调用 LLM；结果不代表 Akane 完整聊天链路的延迟。

```bash
uv run python examples/benchmark_memory_reads.py --repeats 5 --output benchmark.json
```

## 实际改动

- 内存索引在 upsert 时保存 BM25 文档词频和长度，随替换、删除同步更新；每次查询仍在
  已通过硬过滤的候选集合上计算文档频率和平均长度。评分公式、过滤、排序保持原样。
- 来源关系按层、每批最多 400 个 ID 读取，只在本次调用内复用，保持原来的深度优先输出
  顺序、缺失和循环检查。元数据修复或删除后，下一次读取直接使用当前数据库。
- 批量节点查询由逐项三表查询改为每批三表查询；批量打开保留请求顺序、重复 ID 和逐项
  错误。外部存储默认仍委托现有单项 API，无须实现新批量方法。
- 模糊检索安全检查仍检查所有正分候选，但不再为仅用于校验的候选渲染正文。
- 锚点扩窗先读取来源 ID 与轮次 ID，仅对所选完整轮次加载正文；多一次小查询换掉整个
  会话正文的载入。交错写入的同一轮仍完整返回。
- 时间线分页在同次调用内复用已渲染行；每次仍对实际拼接文本调用计数器，不假设 token
  可按消息简单相加。清理规则、日期标题、完整轮次和游标保持原样。

## 验证

新增回归覆盖单向包含与反向不匹配、同一词条满足多个查询词、精确与包含共同命中、原词条
依据及变更后游标失效；性能回归使用 SQL 次数和内容等价断言，不使用不稳定的毫秒阈值。
另覆盖批量读取边界、隔离、顺序、重复、歧义、来源缺失/循环、BM25 替换/删除后的评分
等价，以及有日期标题的分页文本、计数和续页等价。
