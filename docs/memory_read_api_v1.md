# Memory Read API V1

This document is the authoritative reference for MemCore's model-facing read
and evidence-navigation APIs. It complements:

- [`usage_flow_v1.md`](usage_flow_v1.md), which explains host integration;
- [`model_prompt_playbook_v1.md`](model_prompt_playbook_v1.md), which explains
  how the chat model should choose tools;
- [`public_capabilities_v1.md`](public_capabilities_v1.md), which is the
  high-level capability map.

All methods below are namespace-safe facades on `MemorySystem`. SQLite remains
the truth source. These reads do not rewrite, delete, or silently broaden stored
evidence.

## Python facade and native tools

Trusted host code may call `MemorySystem` methods directly. Chat models should
receive the schemas generated by:

```python
from memcore import build_native_memory_tool_specs, dispatch_native_memory_tool

tools = build_native_memory_tool_specs(tool_format="openai")
result = dispatch_native_memory_tool(
    tool_name=tool_call.name,
    arguments=tool_call.arguments,
    mem=mem,
    current=current_raw,
)
```

`tool_format` accepts `openai`, `openai_responses`, `anthropic`, or `plain`.
OpenAI schemas are strict by default. Set `include_material_tool=False` when
the host has no real material loader; do not expose a placeholder tool.

Native dispatch returns an envelope:

```json
{
  "ok": true,
  "status": "ok",
  "tool_name": "open_memory",
  "result": {},
  "receipt": {}
}
```

`ok/status` on the outer envelope report dispatch/protocol validity. After a
successful dispatch, the read's domain state remains in
`result.status/result.reason`. Strict argument or authorization failures use a
structured outer error instead. A host adapter may project this state into its
own envelope, but must not rewrite or broaden the evidence.

Persist the complete result that the model actually received as the correlated
observation in the same turn. It remains visible across later normal turns
until that raw turn reaches the unified token compactor. Persist `receipt`
beside the body as a compact retention/navigation anchor; it never substitutes
for the result. The operation entry is explicit-only in normal retrieval, so
reopening old evidence does not create a second conversational fact source.

## Domain status contracts

Catalog, node-opening, and timeline reads use:

| Status | Meaning |
| --- | --- |
| `ok` | The selected representation was returned completely. |
| `empty` | The selector is valid but no authorized evidence matched. |
| `partial` | Complete units were returned, but lineage or page coverage is incomplete. |
| `invalid_filter` | The selector, view, projection, cursor, or filter combination is invalid. |
| `unavailable` | The authorized store/index cannot safely serve the request. |
| `failed` | The read failed without changing memory truth. |

Retrieval uses its established scoring-oriented states:

| Status | Meaning |
| --- | --- |
| `found` | One or more authorized matches survived filtering and scoring. |
| `empty` | The query was valid but no authorized match survived. |
| `invalid` | A retrieval filter or lineage selector was invalid. |
| `unavailable` | Required lineage storage or the search index was unavailable. |
| `failed` | Retrieval failed without changing memory truth. |

Invalid filters never fall back to a broader search. A cursor continuation must
be called with only `cursor`; selector, scope, view, projection, page size, and
budget are embedded in the cursor.

## `retrieve_for_turn`

Use semantic/BM25 retrieval for a topic, person, preference, relationship,
plan, fact, or event whose exact time is unknown.

```python
texts = mem.retrieve_for_turn(
    current=current_raw,
    query="和 misaka 一起来吃早茶的人",
    entity_anchors=["misaka"],
    topic_terms=["同行", "早茶"],
    source_layers=["raw"],
    memory_facets=["event"],
    about_roles=["third_party"],
    time_hint={"start_at": "2026-08-03 11:00", "end_at": "2026-08-03 12:00"},
    within_memory_id="optional-episode-id",
)
```

Python return type is `list[str]`. Hosts that need diagnostics may call
`retrieve_for_turn_structured(...)` and inspect its `RetrievalResult`.

`retrieve_for_turn` defaults `cross_conversation=True` while retaining the hard
tenant/user/domain namespace and applying asymmetric prompt-visible exclusion:
visible raw entries exclude their derived summary/semantic ancestors, while
visible summary/semantic entries do not permanently hide their downstream raw
evidence.
The native model schema keeps that scope host-owned: it requires `current`,
searches the authorized user's conversations, and does not expose
`cross_conversation`, arbitrary result limits, token budgets, or exclusion IDs
for the model to rewrite. Trusted Python callers may pass those facade filters
explicitly when implementing product policy or diagnostics.

Important parameters:

- `current`: the current raw record; its source is excluded before scoring,
  together with the prompt-visible records and only their derived ancestors
  (downstream raw evidence under a visible summary remains retrievable);
- `query`: always participates in dense and BM25 retrieval;
- `entity_anchors`: only exact entities already known from the question or
  context; never guess the answer being asked for;
- `topic_terms`: supporting actions, attributes, and topics;
- `source_layers`: `raw`, `summary`, and/or `semantic_summary`;
- `memory_facets` / `about_roles`: pre-score metadata filters;
- `time_hint.start_at/end_at`: known start-inclusive/end-exclusive time bounds;
- `within_memory_id`: a hard lineage boundary obtained from browse/open;
- `include_explicit` + `kind_patterns`: host-authorized explicit trace/event/
  material retrieval. They do not open arbitrary kinds.

Normal retrieval excludes operation/tool/material traces. Full tool evidence is
not returned unless the host policy and model request explicitly authorize the
corresponding kind.

The structured/native result includes `matches`, rendered `snippets`, `count`,
`navigation`, `suggested_next_actions`, `effective_filters`, `candidate_counts`,
`lineage_scope`, entity-relaxation diagnostics, token usage, and
omission/truncation state. `navigation` pairs each returned position with the
reloadable top-level ID: summary layers expose `memory_id`; raw layers expose
`source_id` plus available turn/time anchors. Every match and navigation item
also carries a `time` object with local ISO timestamps (`at` for raw,
`start_at/end_at` for summary layers). Candidate counts describe the
pre-ranking pools; the returned matches are the top raw-first ranked results,
not a claim that no other stored record exists. Navigation never copies a
summary's descendant lineage.

The intended loop is explicit:

- answer immediately when the rendered snippet is sufficient;
- use `open_memory(memory_id=..., view="content")` for the full summary;
- when a summary topic is correct but one detail is missing, use
  `retrieve_for_turn(within_memory_id=..., source_layers=["raw"])` to search
  only that node's exact source lineage;
- use `open_memory(memory_id=..., view="sources")` when the complete source
  tree or original evidence is actually required;
- use a raw `source_id` with `read_timeline` only when adjacent turns are
  missing;
- do not issue synonymous retrievals after a useful hit. Retrieve again only
  after obtaining a new known entity, time clue, or materially different
  target.

There is no LLM verifier pass after deterministic retrieval.

## `browse_memory`

Use a deterministic catalog for broad or high-density time ranges.

```python
result = mem.browse_memory(
    time_range={"start_at": "2026-07-22", "end_at": "2026-07-26"},
    node_types=["episodic"],
    cross_conversation=False,
    page_size=50,
)
```

Signature:

```python
browse_memory(
    *,
    time_range=None,
    date_from="",
    date_to="",
    node_types=None,
    cross_conversation=False,
    page_size=50,
    cursor="",
) -> dict
```

Rules:

- choose `time_range` or the `date_from/date_to` mode;
- `date_to` is inclusive in date mode;
- `node_types` defaults to `episodic`; available values are `episodic` and
  `semantic`;
- cards are chronological SQLite range results, not semantic Top-K;
- `page_size` counts complete cards and is bounded to `1..200`;
- a continuation call sends only `cursor`.

Important result fields:

```text
status / reason
coverage.requested_range
coverage.covered_intervals / live_raw_intervals / gap_intervals
coverage.total_source_count / covered_source_count / live_source_count / gap_source_count
cards[]
matched_card_count / returned_card_count / remaining_card_count
page_complete / next_cursor
```

Cards returned by the `MemorySystem` facade include both epoch
`period_start_ts/period_end_ts` and model-readable local ISO
`period_start_at/period_end_at` values.

`coverage.complete=true` means every stored raw source in the requested range
is accounted for. It does not claim the host was online or recording every
real-world event.

## `open_memory`

Open one or several IDs returned by retrieval or catalog browsing.

```python
open_memory(
    *,
    memory_id="",
    memory_ids=None,
    view="card",
    detail="full",
    projection="conversation",
    cross_conversation=False,
    page_size=50,
    cursor="",
) -> dict
```

`memory_id` opens one node. `memory_ids=[...]` batch-opens `card` or `content`
nodes in request order and returns per-node `status/reason`; one unavailable ID
does not discard successful siblings. The two selectors are mutually
exclusive. Batch `sources` returns `invalid_filter/batch_sources_not_supported`
because each lineage tree has its own lossless cursor; call it once per selected
tree instead.

### Views

| Node | `card` | `content` | `sources` |
| --- | --- | --- | --- |
| raw | compact identity | one projected raw entry | `empty/raw_node_has_no_sources` |
| episodic | episode card | full episode summary | complete raw logical units |
| semantic | semantic card | full semantic summary | exact child episode cards |

`detail=full|compact` applies to a raw `content` view. It does not globally
change every source entry.

`projection` applies to episodic raw `sources`:

| Projection | Model-visible evidence |
| --- | --- |
| `conversation` | Default. Messages and events remain full. Action/observation and `operation.*`, `skill.*`, `tool.*`, `material.*` bodies become compact reloadable records. |
| `full` | Every selected raw entry is rendered in full. Use only when the complete mixed trace is necessary. |
| `tools` | Only full action/observation and `operation.*`, `skill.*`, `tool.*` evidence. Standalone `material.*` entries are not included unless their turn role is action/observation. |

A compact record retains the facts needed to understand the trace without
copying its body:

```text
kind and timestamp
source_id
actor / target_actor when present
correlation_id and relation_status
status
small retention/file anchors when present
stored character volume
an exact open_memory(memory_id=..., view="content") reload hint
```

The stored payload remains intact. To inspect one compact operation result:

```python
mem.open_memory(
    memory_id="tool-result-source-id",
    view="content",
    detail="full",
)
```

To inspect every operation body in one episode, explicitly use
`projection="full"` or `projection="tools"`.

Raw `sources` result fields include:

```text
result.source_node_type = raw
result.source_count
result.logical_unit_count / returned_logical_unit_count
result.compacted_entry_count
result.missing_source_ids
result.source_units[]
result.page_complete / next_cursor
text
```

Direct trusted Python calls keep both `source_units` and rendered `text` for
diagnostics. Native dispatch removes the duplicate entry bodies and returns one
rendered `text` body plus `returned_logical_unit_ids` and navigation metadata.
This prevents one source page from occupying the model context twice.

Source pagination is by complete logical units and `page_size`, not a hidden
token truncation. `open_memory` does not silently replace explicit raw evidence
with cards or summaries.

## `read_timeline`

Use exact time or raw-anchor lookup when chronology, wording, attribution, or
nearby context matters.

```python
read_timeline(
    *,
    time_range=None,
    date_from="",
    date_to="",
    time_periods=None,
    anchor_source_id="",
    before_turns=0,
    after_turns=0,
    cross_conversation=False,
    projection="conversation",
    page_token_budget=0,
    cursor="",
) -> dict
```

Selector modes are mutually exclusive:

1. `time_range={start_at,end_at}` for exact start-inclusive/end-exclusive time;
2. `date_from/date_to/time_periods` for local-date or coarse-period reads;
3. `anchor_source_id` with `before_turns/after_turns` for complete nearby turns;
4. `cursor` alone for continuation.

The three projections have the same meaning as episodic raw `sources`.

Python and native page budgets intentionally differ:

- trusted Python: `page_token_budget=0` is unlimited diagnostics;
- native model tool: omitted or zero uses
  `MemoryConfig.native_timeline_page_token_budget`; a larger request is capped
  and a smaller request is respected.

Pagination never splits a logical turn/relation unit. One unit larger than the
page budget is returned whole and reported as `coverage.oversized_unit=true`.

Important result fields:

```text
status / reason / projection
coverage.complete / coverage_complete
selected / returned / remaining logical-unit, entry, and projected-token counts
coverage.compacted_entry_count
coverage.token_count_quality
coverage.oversized_unit
next_cursor / suggested_next_actions
messages / text
```

Direct Python receives both `messages` and `text`. Native dispatch sends only
`text` plus coverage/navigation metadata.

## `read_entry` compatibility adapter

```python
read_entry(*, source_id: str, detail: str = "full") -> dict
```

This is a current-conversation, raw-only compatibility adapter over:

```python
open_memory(memory_id=source_id, view="content", detail=detail)
```

It is not included in newly generated model tool schemas. New integrations
must use `open_memory` so raw, episodic, and semantic IDs share one facade.

## Optional `load_material` host tool

`load_material` is included in native schemas by default, but it is not a
`MemorySystem` file-reading method. The host must pass a real
`material_loader` to `dispatch_native_memory_tool(...)` and remain responsible
for authorization, storage, cleanup state, and content extraction.

```text
load_material(
  file_id,
  kind?,
  preferred_source=auto|original|derived?,
  purpose?
)
```

The model should first obtain an authorized `file_id` from visible memory,
timeline evidence, or explicit material retrieval. A loader may return original
content, OCR/vision text, document chunks, or a structured
`pending/unavailable/expired` state. MemCore rejects a loader result that claims
a different `file_id`; it never fabricates content or treats an identifier as
proof that the file was seen. As with memory reads, persist the sanitized
model-visible result once and keep the receipt beside it as a retention anchor.

## Cache and persistence rules

- tool schemas and descriptions belong to the stable prompt prefix;
- current cards, summaries, raw evidence, and tool results append at the
  dynamic tail;
- changing an API schema causes one expected prompt-prefix version change, not
  per-turn schema churn;
- native `open_memory/read_timeline` results carry one evidence body, not two;
- cross-turn operation memory keeps the one model-visible result body until the
  same raw token lifecycle compacts it; it does not create a turn-scoped shadow;
- compact receipts live beside results as retention anchors and may survive in
  the operation digest after the full body is compacted;
- retrieval receipts retain only reloadable top-level `memory_id`/raw
  `source_id` values. Full `source_ids` and lineage remain in the real result
  and storage layer, so a large summary lineage cannot overflow the compact
  retention anchor or be silently truncated;
- native provider projection emits one result body, never `output` plus a
  second `data.output` rendering of the same evidence.

## Minimal navigation examples

Broad group-chat overview:

```text
browse_memory(date_from="2026-07-22", date_to="2026-07-25")
-> open_memory(memory_ids=[<episode-a>, <episode-b>], view="content")
-> answer from summary, or open_memory(memory_id=<episode>, view="sources")
```

Exact hour:

```text
read_timeline(time_range={"start_at":"2026-08-03 11:00","end_at":"2026-08-03 12:00"})
```

Unknown detail inside a chosen episode:

```text
retrieve_for_turn(query="早茶 同行", within_memory_id=<episode>, source_layers=["raw"])
```

Full body of one compact tool result:

```text
open_memory(memory_id=<tool-source-id>, view="content", detail="full")
```
