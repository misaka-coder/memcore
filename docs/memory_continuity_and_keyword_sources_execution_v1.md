## 已确认的问题及原因

修复前，长期化先取最早的一批阶段摘要，再按实体、话题等重叠度寻找旧长期记忆作为强化目标。合并时只并入旧来源与新批次，却把起止日期扩成两者的最小和最大时间；中间发生过的其他批次不会自动加入。

已核对的问题卡片标注 9 月 27 日至 30 日，实际 10 张来源阶段卡片由 27 日的 5 张和 30 日的 5 张组成。28、29 日有大量已存对话，相关摘要归在其他长期记录中。因此，这里的 10 是来源阶段卡片数，时间范围是首尾包络，不能解释成这条记录连续覆盖了四天。核验时的阶段摘要渲染也不是简单截取每张摘要的前几行。

另外，旧强化调用失败后，合并路径仍可能采用旧正文作为回退，同时扩大日期与来源。这个代码缺口随跨批次合并路径移除而消除；现有证据不能断言该问题卡片当时就发生了模型调用失败。

修复前，卡片关键词池读取摘要及精确来源的已存标签，不检索原文正文。标题或标签遗漏某个话题时，原文即使包含查询词，也可能找不到该卡片。

跨群读取还有独立的宿主问题：目录已在目标群正确返回卡片，下一次 open 未带会话时，宿主使用当前群查找，得到范围外或未找到结果。它不能被解释成原来的跨群访问权限被禁止。

## 长期记忆保持连续来源

长期记忆继续提炼稳定事实、反复话题、重要人物及未完成事项。改动的是来源归组与写入方式：一批连续阶段摘要生成一条新长期记录，后来相似的话题留在后来的记录中，不再覆盖早期记录。

连续的含义是：在同一命名空间、同一会话的阶段摘要顺序中，没有跳过两端之间已存的阶段摘要。它不要求每一天都有发言，也不要求相邻时间戳严丝合缝。真实沉默几天后接着聊天，可以构成连续来源；中间已有摘要却被归到别处，不能包装成一段连续历史。操作摘要仍走既有分区，不混入这条对话长期化链路。

实施时完成以下约束：

- 按可信来源顺序选择批次，并为相同时间建立稳定排序；不能仅靠主题相似或首尾时间判断连续。
- 在生成前及事务提交时校验来源顺序、归属、版本和完整性。遇到旧数据跳段，报告需要修复，不拼接剩余片段继续生成。
- 起止时间、参与者、来源 ID 由系统从本批来源计算；标题、正文和事实字段仅概括本批内容。批次内可以提炼与去重。
- 模型失败、输出无效或来源版本变化时，不提交新正文、不扩大来源、不标记已长期化；沿用明确的失败及重试状态。
- 复用现有批量提交、后台压缩和索引待办机制，不引入第二条写入生命周期。

正常压缩不再调用强化任务。相关配置、提示槽、任务枚举和宿主构造需要一并梳理：旧配置采用明确的兼容弃用说明，宿主停止传入；已有持久化任务标识保持可解释，不改用作另一种任务。不能留下看似能控制强化、实际上无声失效的开关。

阶段卡片和长期卡片仍是显式目录导航对象。是否进入模糊检索继续按原有策略执行，不能把目录能力混同于模糊召回。

## 标签与原文共同匹配卡片

关键词查询先按原有权限、日期、节点类型与参与者条件选出卡片，再批量解析其精确来源。检索正文作为派生读取视图，不把完整发言塞进 entity_anchors、topic_terms，也不新建宿主分类体系。

正文范围包含普通用户发言、旁观群消息、语音转写及正常助手对话，沿用现有普通对话类型定义和正文取值。旁观消息即使不进入模糊检索，也可以在授权卡片来源内参与本次字面匹配。工具、操作、Skill、材料内容及无关隐藏事件不因此开放；不扫描完整 provider JSON 或附件来冒充发言。

匹配规则如下：

1. 标签与正文统一做 NFKC、空白及大小写规范化；保留标点。不增加分词、同义词猜测或模型判断。
2. 单向子串包含：查询词包含在已存标签或正文中才命中。例如“文旅答辩项目”包含“文旅”，反方向不成立。原文显示保留原始字符。
3. any 表示卡片任一来源渠道命中任一查询词。all 表示每个查询词都能在这张卡片的标签或来源正文中找到依据，可以分散在不同消息和渠道，不要求同一句话包含所有词。
4. 原文命中按 source_id 去重。同一消息命中多个词、同一词出现多次，只算一条；不同消息文字相同，仍是不同发言。
5. 同一 memory_id 只返回一张卡片。阶段卡片和其长期父卡片是不同节点，保留原有 node_types 选择；不按标题或相同片段误合并不同节点。

例如查询“文旅、答辩”且使用 all：标签命中“文旅”，某条原文命中“答辩”，这张卡片成立。其原文命中列表包含所有命中任一查询词的真实消息；标签独自提供的词不需要伪造对应原话。

日期仍按现有卡片时间范围重叠语义筛选，不暗改为逐句时间筛选。卡片命中原话显示其实际时间；若需严格限定某天或某分钟内的发言，使用 read_timeline。参与者筛选表示卡片包含这些人，不能自动解释成关键词一定由这些人说出；实际归因依据原话。

尚未形成阶段摘要的近期原文没有父卡片，仍由可见原文或时间线读取。coverage 继续说明筛选前的已存历史；关键词空结果不能被渲染成“没有这段历史”。来源缺失时说明证据不完整，不把可读命中数伪装成全部命中数。

## 卡片精简展示与命中原文续读

可信 Python 结果保留必要的结构化信息；宿主为模型选择紧凑投影。单次结果的会话、查询条件、时区、覆盖情况和目录分页状态只在页头出现一次。混合会话批量结果才在节点处注明不同来源群。

卡片保留 ID、标题、时间、简短关键词与一份参与者名单；已有目录提示仅在提供额外选卡信息时显示。本次匹配附命中词、唯一原文命中数及一个读取凭据。默认最多预览一条短原文，并保留时间、说话者与 source_id；这是展示取样，不是命中集合上限。没有原文命中则不显示空预览和无用读取入口。

以下都是虚构示例，用于审阅展示密度：

```text
群 A｜查询：文旅、答辩（all）｜时区：Asia/Shanghai
覆盖与分页：此处仅显示本次必要信息

card_demo｜文旅项目与答辩安排｜2026-09-28 20:10 至 09-29 00:25
关键词：文旅答辩项目、材料准备｜参与者：小林（QQ 123456）、小周（QQ 654321）
命中：文旅、答辩｜原文 12 条｜原文读取凭据：match_demo
预览：09-28 20:16 小林 source_demo：“文旅答辩的材料我明天整理。”
```

不在每张卡片重复完整 query、conversation 标签、两套日期格式、参与者结构、标签池、摘要正文、全部来源 ID、哈希、空错误或诊断统计。必要的状态和重查原因仍须显示。首次目录返回不铺开 12 条全文，也不另附第二套 snippets。

已在现有 open_memory 增加 match_ref 入口，不新增顶层工具。模型使用目录实际返回的凭据，以下值只是示例：

```json
{"match_ref": "match_demo"}
```

该凭据定位卡片及本次关键词条件，直接读取其后代中匹配的完整原始发言，包括长期卡片下的阶段来源。它是明确标记的“关键词命中片段”，不是整段对话，也不是整个 sources 树。普通 open_memory(memory_id=..., view="sources") 仍按现有规则读完整来源；speaker_ids 的现有实际发言者筛选保持兼容。

续读页只在页头显示卡片、筛选模式、命中总数、本页与剩余数量。每条原话保留实际说话者、时间、source_id 和一份完整正文，按原始顺序排列。上下文不足时，以 source_id 调 read_timeline 扩窗；不默认把周围所有聊天也返回。

沿用 native 读取的有限 token、字节预算及完整消息规则。正常超预算提供续页；单条过大按现有明确状态处理，不静默截断正文。跨卡片共享同一 source_id 时，本页正文只显示一次，保留所属卡片引用，每个续读页可以独立理解。

目录 next_cursor 用于下一批卡片；match_ref 用于启动某张卡片的命中原文读取；读取后返回的 next_cursor 用于这张卡片的下一页原文。三者用途明确，续页只传对应 cursor，不重复整套查询条件。

读取凭据与 cursor 冻结卡片、授权范围、查询词、any/all、匹配版本、来源指纹及分页位置，不携带庞大的全量 source_id 清单。首次凭据不能与另一个 memory_id、筛选条件或范围组合；来源、正文或权限变化后明确要求重查，不拿过期位置继续或自动放宽范围。

模型实际收到的结果作为 observation 存储一次。回执只保留必要导航锚点，不复制正文；终局压缩与回读沿用现有机制，完整导航不能因小回执有界而丢失。工具说明仅补最短规则：卡片给线索，命中数不是全文；需要原话时用读取凭据，不够再续页或扩窗。

## 后续读取延续正确的群范围

宿主从可信工具结果保存卡片与来源会话的对应关系，让 open_memory、within_memory_id 检索和续页继承它。复用现有结果来源和签名包装，不新增必须由模型填写的 namespace 参数。

每次读取仍检查当前发起者、Bot、角色、目标会话及开关。显式指定范围与已知来源冲突，或推导外群范围时缺少可靠来源、多义时，返回清楚的范围错误及可行下一步；显式指定合法会话及原有当前会话读取保持兼容。不从用户文本猜来源，不全库碰运气查找，也不把所有后续请求固定到“最近查过的群”。批量节点各保留自己的可信来源及 cursor。

成功选出群 A 卡片后，后续读取必须实际到群 A；未找到、来源已删除、权限已改变应分别解释，避免一次落错群被模型理解成禁止跨群。

## 旧长期记忆的修复

新机制不能自动纠正已经形成的旧记录。修复通过 MemorySystem 的公开维护入口执行；如现有 facade 缺少能力，先扩展正式 API，宿主不直接改库或调用私有写入方法。

1. **生成只读修复计划。** 按授权会话核对每条旧长期记忆的实际阶段来源与连续性，列出受影响节点、完整来源、缺失情况、预计新记录数量和摘要调用量。修复材料保存在运行环境，不把数据库、日志或真实原话写入仓库文档。
2. **确定完整受影响范围。** 旧记录可能彼此交错。对来源区间反复扩展，纳入被穿插的相关记录及中间阶段摘要，直到整个修复范围能重新按顺序分组。不能只把单张坏卡拆成两端，否则其他交错记录仍旧跳段。
3. **暂存完整新结果。** 仅以保留的阶段摘要重建连续批次；标题、正文、参与者、关键词和来源均来自相同批次。任一生成失败、来源缺失或版本变动，不发布半套结果，保留原状态并报告原因。
4. **原子发布受影响记录。** 提交前复核来源与旧记录版本，在同一存储事务中切换替代记录、来源归属、长期化标记和派生状态。原始对话、阶段摘要正文以及原有模糊检索可见性不改写。受影响范围内每个阶段来源恰好归属一次，无漏项和重复消费；未达到现有长期化批量条件的尾部留待正常处理，不人为补齐。
5. **同步索引及旧引用。** 移除被替代记录的旧索引项，并建立新项；索引失败沿现有待办重试，不能只调用 reindex_all 就宣称旧向量已经清空。同步期间以已发布的 SQLite 记录为准，过期索引不能重新暴露被替代的旧记录。为旧 ID 保存版本与替代节点映射，旧引用得到清楚的修复状态和新入口，不暗指向某一个片段。旧 cursor 明确失效并要求重查。
6. **核对与回滚。** 比较修复前后来源集合、顺序、日期、归属和可读证据，核对索引待办是否收敛。保留有范围和版本条件的回滚记录，避免回滚覆盖期间新增的正常历史；旧快照仅作恢复依据，不作为第二套可检索真相。

先在隔离副本完整验证，再按计划处理实际受影响范围。生成过程中允许继续记录原始聊天；发布时协调该会话的压缩并校验版本，冲突则重新计划。没有保留来源的部分如实报告，不能让模型补写不存在的历史。

## 性能与实施位置

首版采用按来源 ID 批量读取、同次查询共享来源去重和一次正文规范化。先筛卡片，再检查其普通对话正文；不逐卡片重复扫描整个会话，不为未返回卡片渲染全部正文，不在读取时调用 LLM 或 embedding。

已做的只读原型测量提供规模参考，尚不代表新 API 已实现。下表为同机热读取各三次的中位数，额外耗时包含正文读取、规范化及子串检查，不含完整工具包装、网络和模型等待：

| 匿名场景 | 阶段卡片数 | 来源普通对话条数 | 原文检查额外耗时 |
| --- | --- | --- | --- |
| 会话 A 全历史 | 27 | 7972 | 约 65 ms |
| 会话 B 全历史 | 162 | 31956 | 约 296 ms |
| 会话 B 近四天 | 44 | 6052 | 约 68 ms |

原型中标签与原文各补到了另一方遗漏的卡片，支持两者取并集；大范围正文扫描确有成本。首版先用批量读取验证实际延迟，只有规模测试证明必要时再单独评估子串索引。任何后续加速都必须保留短中文词和最终包含判定，不能靠限制查询长度规避问题。

| 边界 | 实施位置与职责 |
| --- | --- |
| MemCore 长期化 | compaction 与事务提交：连续批次、新记录、失败不写入 |
| MemCore 存储读取 | SQLite 来源批量查询：标签与原文匹配，版本与指纹 |
| MemCore 公共读取 | MemorySystem、来源读取、native dispatch：卡片命中概况、读取凭据及分页 |
| MemCore 维护 | 公开修复计划与应用入口、替代映射、索引待办及回滚 |
| Akane 适配 | 记忆读取策略、工具处理与 timeline 渲染：来源范围、签名、紧凑展示及 observation |
| 文档和提示 | 更新配置、生命周期、读取契约与简短工具说明；不重复塞入整篇执行文档 |

## 执行顺序与验收

用户确认本文后，依次完成：新长期化机制及故障验证；标签加原文的卡片匹配与命中续读；宿主来源范围和精简渲染；隔离旧数据修复演练；完整检查后更新运行包并处理实际受影响历史。每个切片先验证真实调用链，再推进下一步。

重点验收以下行为：

- **连续性。** 27 日话题 A、28 日 B、29 日 C、30 日再出现 A；新长期记忆不能跳过 B、C 去强化早期 A。真实沉默空档、多天连续批次、同时间来源均能正确处理。
- **失败与旧数据。** 摘要失败、提交冲突和索引失败不造成假成功；交错旧记录修复后来源无漏项、无重复归属，旧 ID 可解释、旧 cursor 要求重查，回滚不覆盖新历史。
- **命中与去重。** 标签独有、原文独有、两者同时命中、跨消息 all、短中文、重复词、多词同一消息、相同文字不同消息、旁观及语音均正确；完整命中集合可逐页读完。
- **范围与证据。** 卡片关键词和参与者条件继续取交集；群 A 卡片在群 B 发起后续读取仍定位群 A；混合批量、权限改变、来源删除和过期凭据均返回明确结果。
- **展示。** 同等卡片数下，模型结果新增量仅来自必要命中字段和短预览；普通查询不增添空字段。原文续读只有一份正文，目录不混入全部命中，回读与终局压缩后的导航仍有效。
- **原有能力。** 模糊检索候选策略与排序不变，旁观排除不变；普通 sources、批量读取、speaker_ids、操作和材料权限继续符合原契约。
- **速度。** 比较全历史与日期范围、单词与多词、少命中与大量命中，记录 SQL 次数、读取量、完整工具延迟及模型输入字节。次数不随卡片数逐张增长，不用原型数字承诺所有场景的延迟。

### 群内复测日志补验

同日复测检查了正式更新之后的模型实际工具结果，发现两项残留问题，并在宿主适配层补齐：

- **失败读取污染来源判断。** 一次历史 `empty` 返回只是在回显错误查询范围，却被宿主当作卡片的成功来源，导致同一卡片连续四次报 `ambiguous_memory_conversation`，包括已经显式指定正确范围的请求。来源导航现在只接纳成功、有效的部分返回及替代入口；失败或空返回不建立归属。真正的成功来源冲突仍保持拒绝，用户引用也不能建立来源。
- **未读完被称为完整。** 一次原话补读仅返回 1,889 条中的 118 条，剩余 1,771 条尚未续读；另一时间范围读完两页后仍剩 77 条。工具已有分页标记，但重复 ID 列表和统计占据了大量元数据。时间线投影现在只显示一份统计和续读凭据，保留实际已读起止、剩余数量及异常覆盖信息，并增加一句未读完整的提示。正文、授权、凭据、分页预算和检索候选不变。

新增回归先复现旧行为，再验证省略范围、指定范围、批量打开均恢复，同时核对实际工具链的分页续读、归属、无重复原话及完整结束状态。宿主相关测试由 209 项增至 211 项，全部通过；改动文件 Ruff 检查及两仓库 `git diff --check` 通过。

实际测试历史的隔离副本中，四张被选卡片的正文均可打开，包括此前报错的第四张；四张来源判断均指向用户所选会话。三份已保存时间线结果重新投影后，元数据分别从 14,869／15,006／14,478 字节降至 2,598／2,593／2,501 字节，正文和续读凭据逐份一致。指定上午范围的 318 个逻辑单元可以续读完，无遗漏或重复；此项读取没有调用 LLM 或 embedding。
